# 用 LeanCloud 保存牌局

已结束的牌局改存 LeanCloud 开发版，换手机或清掉网站数据后还能找回。进行中的这一桌继续只存在本机，避免半局数据上传。每家俱乐部有两个口令：读口令只打开这一家，写口令才能记牌和删除。分享链接保持现在的只读快照。

这次只记录方案，代码下次再做。

## 访问方式

在 LeanCloud 控制台建一个开发版应用，节点选国内。不预先建俱乐部用户。新建一家时设定两个不同的口令，并生成两个用户：用户名分别是读口令、写口令的哈希，口令本身不明文写进用户名。读用户的 `role` 是 `read`，写用户的 `role` 是 `write`。口令不进仓库。

打开网站时输入读口令，用哈希去登录。登录失败，就可以新建一个空的：填写俱乐部名字，并同时设定写口令。先注册读用户并记住读会话，再注册写用户、保存 `Club`，然后退出写用户，用 `AV.User.become` 回到读会话。登录成功而且 `role` 为 `read`，就留下会话，读出这家的名字、牌局和排名；页面上不能记牌，也不能删除。登录成功但 `role` 为 `write`，说明这是写口令，立刻退出，不留在本机，也不打开或新建。

记牌、删除或改名字时再输入写口令。`leancloud-storage` 在本机只保存一个当前用户，`logIn` 会盖住读会话。先把读用户的 sessionToken 留在内存里再登录。登录失败则读会话不动。登录成功后，这个用户必须是这家 `Club` 上的 `writeUser`，动作才写到服务器；别人家的写口令不能改这一家。只要写登录成功，无论这次写不写、成不成功，都 `logOut` 写用户，再 `become` 回读会话。写口令和写会话都不写入本机。若在换回之前关掉页面，下次打开时当前用户的 `role` 若是 `write`，退出并重新输入读口令。

读口令的会话留在本机，之后不用每次再输。换一家时重新输入另一个读口令。带 `#g=` 或 `#c=` 的分享链接不需要口令，仍然是只读快照，不会写回服务器。

网页里只放 App ID、App Key 和 Server URL，用 Vite 环境变量，写在 `.env.local`（已被 `.gitignore` 的 `*.local` 忽略）。Master Key 不进网页，只放在云引擎。

`_User` 关闭公开查询。`role` 只在建号时写入，云引擎拒绝之后的修改。`Club` 和 `Game` 关闭公开读写，对象 ACL 给读用户只读、给写用户读写。对象 ACL 管不到新建，所以类的创建仍对登录用户开放，由云引擎决定拒绝还是收下。`beforeSave` 处理 `Club` 和 `Game` 的新建与修改，`beforeDelete` 处理 `Game` 的删除：按云端 `Club.writeUser` 核对当前用户，不是这家的写用户就拒绝，并强制写成上述 ACL，不采用客户端提交的 ACL。新建 `Club` 时，当前用户必须就是写上的 `writeUser`，且 `role` 为 `write`，`readUser` 是另一位 `role` 为 `read` 的用户。只拿读口令的人，改客户端也删不掉、记不上。

## 俱乐部名字

每家俱乐部有一条 `Club` 记录，保存 `name`，以及指向读用户、写用户的 `readUser`、`writeUser`。新建时填写名字，和这家的牌局一起存在云端。打开之后，页面标题显示这个名字，不再显示 Texas Hold'em Poker Club。点进某一局时，标题仍是那一局自己的名称。

`Club` 关闭公开读写。读用户只读这条记录，写用户可以改 `name`。`readUser` 和 `writeUser` 建好后不能改。改名字要输入这家的写口令。整份俱乐部的分享快照带上当时的名字，打开链接的人能看到这个名字。

## 现有用户

这次方案还没上线，现在手机里的牌局不会上传。新版本发布之前，大家仍像现在这样只存在各自浏览器里。

新版本打开后，旧牌局先留在这台手机上。有人新建一家俱乐部，云端是空的，并输入写口令确认后，才把这台手机上已经保存的牌局上传一次。正在打、还没保存的这一桌不上传。

另一台手机如果也有旧牌局，再打开这家已经有数据的俱乐部时，不再上传，页面显示云端那一份。所以第一台确认上传的手机，决定这家最初的历史。

## 数据

一条 `Club` 记录保存 `name`、`readUser`、`writeUser`。一条已结束的牌局对应一条 `Game` 记录：`club`、`id`、`title`、`playedAt`、`oneBuyIn`、`players`。`Game` 使用和这家 `Club` 相同的 ACL：读用户只读，写用户读写。排名仍在浏览器里用现有的 `standings` 计算。

两部手机同时保存时，各自新增自己的那一局，不会整份互相覆盖。打开页面、从后台回到前台时重新拉取。

## 代码

- 新增 `src/cloud.ts`：初始化 `leancloud-storage`、用读口令打开已有俱乐部、写用户登录则立即退出、新建时保存名字并同时设定读写口令、列出牌局、用写口令新增、删除和改名字。每次写登录都先记住读会话的 sessionToken，结束后 `logOut` 再 `become` 回去。
- 新增云引擎钩子：锁住 `_User.role`，并在 `Club`、`Game` 上拒绝读用户的新建、修改和删除，强制读用户只读、写用户读写的 ACL。
- `src/storage.ts` 继续管进行中的这一桌，并缓存最近一次拉到的牌局，断网时页面仍能显示上次的结果。不缓存写口令，也不缓存写会话。
- `src/App.tsx` 里现在每次 `club` 变化都会整份 `saveClub`。改成：记录一局时先核对写口令并写入 LeanCloud，成功后再清空这一桌；删除和改名字时同样先核对写口令，失败则保留原样并提示。打开俱乐部后，标题用这家的名字。只打开读口令时，记牌、删除和改名字不可用。
- 本机若已有旧牌局、刚打开的这家云端还是空的，用写口令确认后上传一次。这家云端已有数据时，以云端为准。
- 测试不连真服务器，覆盖读口令不能新建牌局、写口令不能打开俱乐部、写完仍是读会话、写口令不匹配时不丢当前这一桌、保存失败，以及空云端才上传本地旧数据。

## 上线前需要准备的

在控制台创建应用，把 App ID、App Key、Server URL 配进本地环境。关闭 `_User` 的公开查询，以及 `Club`、`Game` 的公开读写。部署云引擎钩子，Master Key 只配在云引擎。读写口令不在控制台里预建，第一次在网页里新建俱乐部时才设定。代码接好后再构建并发布到现在的 Netlify 站点。
