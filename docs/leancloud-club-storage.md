# 用 LeanCloud 保存牌局

已结束的牌局改存 LeanCloud 开发版，换手机或清掉网站数据后还能找回。进行中的这一桌继续只存在本机，避免半局数据上传。全员共用一个俱乐部口令，不给每人单独开账号。分享链接保持现在的只读快照。

这次只记录方案，代码下次再做。

## 访问方式

在 LeanCloud 控制台建一个开发版应用，节点选国内。建一个用户，用户名固定，口令就是俱乐部口令。口令只存在 LeanCloud，不进仓库。

网页里只放 App ID、App Key 和 Server URL，用 Vite 环境变量，写在 `.env.local`（已被 `.gitignore` 的 `*.local` 忽略）。Master Key 不进网页。

`Game` 类关闭公开读写。每条记录的权限只给这个登录用户。别人即使拿到 App Key，未登录也读不到、改不了。

第一次打开需要输入口令。登录成功后的会话留在本机，之后不用每次再输。口令改了或会话失效时，再回到输入口令的页面。带 `#g=` 或 `#c=` 的分享链接不需要口令，仍然是只读快照。

## 数据

一条已结束的牌局对应一条 `Game` 记录：`id`、`title`、`playedAt`、`oneBuyIn`、`players`。排名仍在浏览器里用现有的 `standings` 计算。

两部手机同时保存时，各自新增自己的那一局，不会整份互相覆盖。打开页面、从后台回到前台时重新拉取。

## 代码

- 新增 `src/cloud.ts`：初始化 `leancloud-storage`、登录、列出牌局、新增、删除。
- `src/storage.ts` 继续管进行中的这一桌，并缓存最近一次拉到的牌局，断网时页面仍能显示上次的结果。
- `src/App.tsx` 里现在每次 `club` 变化都会整份 `saveClub`。改成：记录一局时先写入 LeanCloud，成功后再清空这一桌；删除时先删服务器上的记录，失败则牌局还留在列表里并提示。
- 本机若已有旧牌局、云端还是空的，登录后上传一次。云端已有数据时，以云端为准。
- 测试不连真服务器，覆盖登录失败、保存失败时不丢当前这一桌、以及空云端才上传本地旧数据。

## 上线前需要准备的

在控制台创建应用和那个用户，把 App ID、App Key、Server URL 配进本地环境。口令自己留着，第一次打开网页时输入。代码接好后再构建并发布到现在的 Netlify 站点。
